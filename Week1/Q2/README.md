# 問2｜ワーカープール（Worker Pool）

## 目標
限られた数のゴルーチン（ワーカー）で大量のタスクを効率的にこなす「ワーカープール」パターンを学びます。

## 今回の演習で学ぶこと
この問題では、限られたリソース（ゴルーチン）で大量のタスクを効率的に処理する「ワーカープール」パターンの実装を、以下の4つの重要ポイントに注目して学びます。

**1. ワーカー関数の実装（職人の定義）**
ジョブを受け取り、処理結果を返す「職人（ワーカー）」の役割です。
```go
func worker(id int, jobs <-chan int, results chan<- int) {
    for j := range jobs {
        results <- j * 2 // 仕事をして結果を返す
    }
}
```
- `jobs <-chan int`: 受信専用の仕事リストチャネルです。ここからタスクを引き出します。
- `results chan<- int`: 送信専用の完成品チャネルです。ここへ処理結果を納品します。
- `for j := range jobs`: 仕事リストが空になる（かつチャネルが閉じられる）まで、無限に働き続けます。

**2. バッファ付きチャネルの作成（作業台の準備）**
ジョブを溜めておくための「作業台（キュー）」の役割です。
```go
numJobs := 5
// バッファ5のチャネルを作成（5個までならブロックせずに投入可能）
jobs := make(chan int, numJobs)
results := make(chan int, numJobs)
```
- なぜバッファ付きなのか？: 依頼主（メイン処理）が「職人の空き」を待たずに、作業台にまとめて仕事をドサッと置けるようにするためです（非同期性の向上）。

**3. 複数のワーカー起動と終了通知（プールの稼働）**
並行して働く職人のチーム（プール）を作り、最後に仕事の終わりを告げます。
```go
// 3人の職人を同時に雇う（並行処理）
for w := 1; w <= 3; w++ {
    go worker(w, jobs, results)
}

// 作業台に5つの仕事を置く
for j := 1; j <= numJobs; j++ {
    jobs <- j
}
close(jobs) // 「これで今日の仕事は全部だよ」とお知らせする
```
- `go worker(...)`: 複数のゴルーチンを立ち上げることで、1つの仕事リスト（`jobs`）を3人で奪い合いながら高速に消化します。
- `close(jobs)`: これがないと職人（ワーカー）は「まだ仕事が来るかも」と待機したままになり、メモリリーク（ゴルーチンリーク）の原因になります。


**なぜワーカープールか？**
10万件のタスクがあるからといって10万個のゴルーチンを立ち上げると、メモリやスケジューリングの負荷でシステムが不安定になることがあります。固定数のワーカーで回すことで、安全かつ安定したシステムを構築できます。

## 問題文
`main.go` の `___` の部分を埋めてプログラムを完成させてください。

1. `worker(id, jobs <-chan int, results chan<- int)` を完成させてください。
2. `range jobs` でタスクを受け取り、値の2倍を `results` に送信してください。
3. `main` でジョブと結果チャネルを作成し、3つのワーカーを起動してください。
4. 1〜5のジョブを送信後、`close(jobs)` してください。

## ヒント
- `for j := range jobs { results <- process(j) }` でワーカーの骨格ができる
- `close(jobs)` すると全ワーカーの `range jobs` ループが順次終わる
