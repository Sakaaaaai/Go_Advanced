# 問5｜エスケープ解析とメモリ管理

## 目標
Goのコンパイラが変数をスタックとヒープのどちらに割り当てるかを決める「エスケープ解析（Escape Analysis）」の仕組みを理解します。

## 今回の演習で学ぶこと
この問題では、Goのコンパイラが変数を「どこに（スタックかヒープか）」配置するか自動で判断する「エスケープ解析」を、以下の3つの重要ポイントに注目して学びます。

**1. クリエイト・オン・スタック（スタック割り当て）**
関数の中だけで使い切って捨てる変数が置かれる「作業机（スタック）」です。関数が終わると同時に自動でパッと消えるため、後片付け（ガベージコレクション）の手間ゼロで非常に高速です。
```go
func createOnStack() int {
    x := 10
    return x // 「値のコピー」だけを返す
}
```
- ここでは `x` という実体は `createOnStack` が終わると消滅しますが、`10` という中身のコピーだけを呼び出し元に渡すため、スタックのまま安全に処理できます。

**2. クレイイト・オン・ヒープ（ヒープへのエスケープ）**
関数が終わった後も外の世界で長く使われる変数が置かれる「倉庫（ヒープ）」です。
```go
func createOnHeap() *int {
    y := 20
    return &y // 「変数の場所（ポインタ）」を返す
}
```
- `return &y`: 変数 `y` の「住所（ポインタ）」を外に渡しています。もし `y` が作業机（スタック）に置かれたままだと関数終了と共に消えてしまい、呼び出し元が困ってしまいます。
- そのためGoの賢いコンパイラは「あ、これは外で使われるな」と自動的に察知し、安全な倉庫（ヒープ）へ引っ越し（エスケープ）させてくれます。

**3. gcflags によるエスケープ解析の確認**
コンパイラが「どこに置くべきか」を具体的にどう判断したのか、その心の声（思考プロセス）を直接覗き見る強力なコマンドです。
```bash
go build -gcflags="-m" main.go
```
- `-gcflags="-m"`: メモリ割り当ての判断ログを出力させるオプションです。
- 解析ログに `escapes to heap`（ヒープに逃げたぞ）と表示されれば、その変数はスタックからヒープへ引っ越したことが確定します。「いかにスタックに留めるか」がGoの高速化の鍵となります。




**なぜエスケープ解析を知る必要があるのか？**
ヒープ割り当て（エスケープ）が増えると、GCの回数が増えてプログラムの一瞬の停止（Stop the World）が発生しやすくなります。パフォーマンスが要求される場面では、「いかにスタックに留めるか」を意識することが重要になります。

## 問題文
`main.go` の `___` の部分を埋めてプログラムを完成させてください。

1. `createOnStack()` 関数：`int` 型変数を作成し「値」で返してください（スタック）。
2. `createOnHeap()` 関数：`int` 型変数を作成し「ポインタ」で返してください（ヒープへエスケープ）。
3. `go build -gcflags="-m" main.go` を実行して、「escapes to heap」のメッセージを確認してください。

- ポインタを返す：`return &a`（ヒープへエスケープ）
- `-gcflags="-m -m"` で更に詳細な情報が見られる
