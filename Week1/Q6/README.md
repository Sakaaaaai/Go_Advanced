# 問6｜pprofによるプロファイリング（1）CPUプロファイリング

## 目標
`net/http/pprof` を使って稼働中のGoアプリのCPUプロファイル情報を取得・可視化し、どの関数がボトルネックかを特定する方法を学びます。

## 今回の演習で学ぶこと
この問題では、稼動中のプログラムからパフォーマンス情報を引き出す「pprof」によるプロファイリングを、以下の3つの重要ポイントに注目して学びます。

**1. ブランクインポートによるハンドラー登録**
通常は使わない「パッケージ名にアンダーバーを付ける」特殊なインポート方法です。
```go
import _ "net/http/pprof"
```
- `import _ "..."`: 中の関数を直接呼び出すことはないけれど、パッケージが読み込まれた瞬間の「初期化処理（`init()`）」だけは実行してほしい、という時に使うテクニック（ブランクインポート）です。
- これを1行書くだけで、Goのシステムに隠されたプロファイリング用のURL（エンドポイント）が裏側で自動的に登録されます。

**2. プロファイリング用サーバーの起動**
メインのアプリの動きを一切邪魔することなく、計測用の情報を外から見れるようにするための「観察用の小窓」をバックグラウンドに開ける工程です。
```go
go func() {
    http.ListenAndServe(":6060", nil)
}()
```
- `go func()`: `http.ListenAndServe` は実行するとそこでプログラムの進行がストップ（ブロック）してしまう性質があります。
- ゴルーチンを使って背後に回すことで、メインの処理は通常通り走らせたまま、6060ポートでパフォーマンス情報を待ち受ける状態を作れます。

**3. プロファイル情報の取得と解析**
アプリが動いている最中に、「今、どこで一番時間がかかっているか」という証拠データを引っこ抜く魔法のコマンドです。
```bash
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30
```
- `go tool pprof`: Goに標準で備わっている超強力な分析ツールを開きます。
- `?seconds=30`: サーバーに「今から30秒間のCPUの動きを記録して提出せよ」と命令を出しています。この結果を見ることで、当てずっぽうではない「データに基づいた確実なパフォーマンス改善」が可能になります。



**計測の鉄則**
パフォーマンス最適化の第一歩は「推測するな、計測せよ」です。pprofを活用することで、勘に頼らず、データに基づいた確実な修正ポイントを見つけ出すことができます。
