# 問1｜パイプライン・パターン

## 目標
チャネルを使って複数の処理段階（ステージ）を直列に繋ぎ、データをストリームとして効率よく処理する「パイプライン・パターン」を学びます。

## 今回の演習で学ぶこと
この問題では、大量データを「流しながら処理する」Goの並行処理の代表的なデザインパターンである「パイプライン・パターン」を、以下の3つのポイントに注目して学びます。

**1. ジェネレーター関数の実装（最初のステージ）**
データを生成してチャネルに流し込む、工場の「素材投入口」のような最初のステージです。大量のデータをメモリに一度に抱え込むのではなく、少しずつ後続へ流す役割を持ちます。
```go
out := make(chan int)
go func() {
    for _, n := range nums {
        out <- n
    }
    close(out) // 送信完了後に必ず閉じる
}()
```
- `go func()`: データの送信を別ゴルーチンで非同期に行うことで、メインの処理を止めずに次の処理へ進めます。
- `close(out)`: 全てのデータを送り終えたらチャネルを閉じます。これを忘れると、受信側が「まだデータが来るかもしれない」と永遠に待ち続け（デッドロックに）なってしまいます。

**2. スクエアラー関数の実装（中間ステージ）**
前のステージから受け取ったデータを加工（ここでは2乗）して、さらに次のステージへパスする「加工ライン」です。
```go
// 受信専用チャネルとして受け取る
func squarer(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        for n := range in { // inチャネルからデータを受信し続ける
            out <- n * n  // 加工してoutチャネルへ送信
        }
        close(out) // 受信元のinが閉じられ、ループが終わったらここも閉じる
    }()
    return out
}
```
- `<-chan int`: 引数で受け取るチャネルを「受信専用」に制限し、誤って送信してしまう設計ミスを防ぎます。
- `for n := range in`: 送信元がチャネルを `close` するまで、ループしてデータを自動的に受け取り続けます。

**3. メイン関数でのステージ連結（最終ステージ）**
作成した各ステージを直列に繋ぎ合わせ、最終的な結果を取り出す「出荷口」です。
```go
in := generator(2, 3)
out := squarer(in)

for n := range out {
    fmt.Println(n) // 最終結果を出力
}
```
- `in` と `out` のチャネルをパイプのようにつなぎ合わせることで、データが生成 → 加工 → 出力と流れる美しい「パイプライン」が完成します。
- これにより、1つの巨大なデータを処理するのではなく、小さなデータを次々と処理（ストリーム処理）できるようになり、メモリ効率が劇的に向上します。
