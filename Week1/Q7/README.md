# 問7｜pprofによるプロファイリング（2）メモリリーク検出

## 目標
`pprof` のヒーププロファイルを使って、継続稼働のうちメモリを食い尽くしていく「メモリリーク」を特定する方法を学びます。

## 今回の演習で学ぶこと
この問題では、長期稼働時に発生しやすい「メモリリーク」の再現とその検出方法を、以下の3つの重要ポイントに注目して学びます。

**1. インポートとサーバー起動（復習）**
Q6と同様に、外部からアプリの内部状態を覗き見るための「観察用の小窓」を開けておく準備をします。
```go
import _ "net/http/pprof"

func main() {
    go func() { http.ListenAndServe(":6060", nil) }()
    // ...
}
```
- メモリリークは「長時間動かして初めて発覚する」厄介なバグのため、いつでも外から様子を見られるようにしておくことが実運用では非常に重要です。

**2. メモリーリーク関数の実装**
ここでは意図的に、使ったメモリがどんどん溜まっていく「悪いコード」を書いて、現象を再現します。
```go
var leakySlice [][]byte  // グローバル変数（アプリ終了まで残り続ける）

func memoryLeak() {
    for {
        data := make([]byte, 1024*1024) // 1MB確保
        leakySlice = append(leakySlice, data) // グローバル変数へ無限に追加
        time.Sleep(1 * time.Second)
    }
}
```
- `make([]byte, 1024*1024)`: メモリを1MB分確保します。
- ポイント：通常、関数内の変数は「使い終わったらお掃除（GC）」されますが、外にあるグローバルな `leakySlice` に紐付けてしまうと「まだ使っている」とみなされ、永遠にお掃除されずメモリがパンクしてしまいます。

**3. ヒーププロファイリングによる特定**
実際にどの関数が犯人となってメモリを食いつぶしているかを見つけ出す工程です。
```bash
go tool pprof http://localhost:6060/debug/pprof/heap
```
- `.../debug/pprof/heap`: CPUではなく「現在のメモリ（ヒープ）の使用状況」のスナップショットを取得するコマンドです。
- これを使うと、何万行もあるプログラムの中から「`memoryLeak` 関数の `append` の部分が全体の99%のメモリを占有している」といった事実を一発で突き止めることができます。




**実現場でのメモリリーク**
「なぜか数日おきにサーバーが落ちる」といったトラブルの多くは、このメモリリークが原因です。グローバル変数への入れすぎや、終わらないゴルーチンには特に注意が必要です。pprofによるヒープ確認を習慣づけましょう。
