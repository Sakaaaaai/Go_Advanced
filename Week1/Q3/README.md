# 問3｜Fan-out / Fan-in

## 目標
1つのチャネルから複数のゴルーチンへデータを分散（Fan-out）し、それらの結果を再び1つのチャネルへ集約（Fan-in）するパターンを学びます。

## 今回の演習で学ぶこと
この問題では、1つのチャネルを複数に分散し、再び1つに集計する「Fan-out / Fan-in」パターンを、以下の3つの重要ポイントに注目して学びます。

**1. Fan-out（ファンアウト：分散）の実装**
1つのデータソース（チャネル）から送られてくる大量の仕事を、複数のワーカーに分配（Fan-out）する構成です。
```go
// generatorから来た1つのストリームを、2つのworkerに並列処理させる
out1 := worker(in)
out2 := worker(in)
```
- ゴルーチンを使って同じ入力チャネルから複数人でデータを受信することで、自動的に作業が分散され、全体のスループット（処理能力）が向上します。

**2. Fan-in（ファンイン：集約）の実装（merge関数）**
複数のワーカーが別々のチャネル（`out1`, `out2`）に出力した結果を、再び1つのチャネルにまとめ上げる（Fan-in）工程です。
```go
func merge(cs ...<-chan int) <-chan int {
    var wg sync.WaitGroup
    out := make(chan int) // 最終的な１つの出力チャネル
    
    // 各チャネルのデータをoutに流す専用職人
    output := func(c <-chan int) {
        for n := range c { out <- n }
        wg.Done() // このチャネルの処理が終わったら完了報告
    }
    
    wg.Add(len(cs))
    for _, c := range cs { 
        go output(c) // チャネルの数だけ専用職人を起動
    }
    // ...
    return out
}
```
- `cs ...<-chan int`: 可変長引数を使うことで、2つでも10個でも、任意の数のチャネルを引数として受け取れる柔軟な設計にしています。
- `sync.WaitGroup`: 全ての専用職人（ゴルーチン）がデータの転送を終えるのを漏れなく待つためのカウンターです。

**3. マージ完了の待機とクローズ**
全てのワーカーが仕事を終えた後、安全に出力チャネルを閉じる終了処理です。メインの処理を止めないよう、別ゴルーチンで待機するのが鉄則です。
```go
go func() {
    wg.Wait()  // 全ての output ゴルーチンが完了するまで待つ
    close(out)  // 終わったら、最終出力チャネルを安全に閉じる
}()
```
- `go func()`: もしここで `go` を付けずに `wg.Wait()` してしまうと、データが読み出される前にメインの流れがストップしてしまい、誰も `out` からデータを受け取れなくなってプログラムがフリーズしてしまいます。




**活用のメリット**
複数の外部APIを叩いて最速の結果を取得したり、大規模な計算を複数のCPUコアに分散させて最後に集約したりする際、このパターンは非常に強力な武器になります。

## 問題文
`main.go` の `___` の部分を埋めてプログラムを完成させてください。

1. Fan-out：`generator` の出力を2つの `worker` に同時に渡して `out1`, `out2` を得てください。
