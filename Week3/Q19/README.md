# 問19｜GraphQLサーバーの実装

## 目標
クライアントが「欲しいデータだけ」を柔軟に指定して取得できるAPI規格「GraphQL」のスキーマ定義言語（SDL）の書き方を学びます。

## 今回の演習で学ぶこと
この問題では、クライアントが欲しいデータだけを柔軟に指定して取得できるAPI規格「GraphQL」の、スキーマ定義言語「SDL」の書き方を、以下の3つの重要ポイントに注目して学びます。

**1. データ型の定義（Type）**
サーバー側が「どんなデータを持っているか」を、クライアント側へ明確に約束する「型（スキーマ）」を定義する工程です。
```graphql
type User {
    id: ID!        // 重複しない一意のID
    name: String!  // 文字列の名前
    age: Int       // 整数の年齢
}
```
- `!（エクスクラメーションマーク）`: これがついているフィールドは「Non-null（必ず値が入っている）」という強力な保証になります（必須項目）。
- ついていないフィールド（`age: Int` など）は `null` が返ってくる可能性がある（オプショナル）ことを意味します。これにより、クライアント側（フロントエンド）は安全にコードが書けます。

**2. 読み取り操作の定義（Query）**
クライアントから「こんなデータが欲しい」とリクエストする時の「入り口（関数のようなもの）」を定義する工程です。REST APIの `GET` に相当します。
```graphql
type Query {
    user(id: ID!): User
}
```
- 「取得には絶対に `id` が必要で、結果としてさきほどの `User` 型を1件返すよ」というルール（APIの仕様）を定めています。

**3. オーバー / アンダーフェッチングの抜本的解決**
ここがGraphQL最大の存在意義です。「必要なデータを、必要な分だけ」取得できます。
- **オーバーフェッチング**: REST APIによくある「リスト表示で名前だけ欲しいのに、APIを叩くと住所や生年月日や過去の履歴まで全部（メガバイト級のデータ）送られてきてしまい、画面表示が遅くなる」問題のことです。
- GraphQLでは、呼び出す側（クライアント）が「このクエリでは `id` と `name` だけ返して」とリクエスト時に細かく指定できるため、無駄な通信量が一切発生せず、モバイル回線でも超高速に画面を描画できるようになります。




## 問題文
定数 `GraphQLSchema` に以下の内容のGraphQLスキーマ文字列を完成させてください：

1. `id(ID!, 必須)`, `name(String!, 必須)`, `age(Int, オプショナル)` を持つ `User` 型を定義してください。
2. `user(id: ID!): User` を返す `Query` 型を定義してください。
