# 問21｜WebSocketによるリアルタイム通信

## 目標
HTTPのリクエスト/レスポンスを超えた「双方向リアルタイム通信」を実現するWebSocketの基礎と、GoでのエコーサーバーとはWebSocketとはどのようなものか学びます。

## 今回の演習で学ぶこと
この問題では、常時接続によるリアルタイム通信を実現する「ウェブソケット（WebSocket）」の基礎を、以下の3つの重要ポイントに注目して学びます。

**1. アップグレード処理（Switching Protocols）**
「一問一答」で終わってしまう通常のHTTP通信から、電話のように「繋ぎっぱなし」のWebSocket通信へと回線を切り替える（アップグレードする）工程です。
```go
// wとr（HTTPの要求と応答）を渡し、双方向通信用の「conn（コネクション）」を手に入れる
conn, err := upgrader.Upgrade(w, r, nil)
```
- クライアントからの「WebSocketで話しませんか？」というリクエストに対し、サーバーが「いいですよ」と返すことで、永続的な双方向専用のトンネルが開通します。

**2. 接続の終了予約（Defer Close）**
電話をかけ終わったら必ず受話器を置くように、通信終了時の後片付けを予約してサーバーのメモリを守る工程です。
```go
defer conn.Close()
```
- 万が一クライアントが突然スマホの電源を切って通信が途絶えた場合でも、関数を抜ける際に `Close()` が必ず呼ばれます。これにより、「幽霊のように残り続けるコネクション（リソースリーク）」を防ぐことができます。

**3. 通信ループ（Read / Write）**
トンネルが繋がっている間、延々とメッセージのキャッチボールをし続ける工程です。
```go
for { // 無限ループで待ち構える
    // 相手からのメッセージを受信する（メッセージが来るまでここで一時停止して待つ）
    mType, msg, err := conn.ReadMessage()
    if err != nil { break } // 切断されたりエラーが起きたらループを抜けて終了
    
    // 受け取った内容（msg）を、そっくりそのまま相手に投げ返す
    conn.WriteMessage(mType, msg)
}
```
- この `for` ループが回っている間は通信がずっと維持されています。
- ここでは受け取ったデータをそのまま返す「エコーサーバー」を作っていますが、実際のチャットアプリでは、ここで受け取った `msg` を「今繋がっている他の全員（コネクションのリスト）」へ一斉送信（ブロードキャスト）する処理を書きます。




**リアルタイムなWeb体験**
チャット、株価の更新、オンラインゲーム、共同編集ツールなど、ページをリロードせずに「向こうから勝手に情報が届く」体験は、すべてこのウェブソケットの技術に支えられています。
