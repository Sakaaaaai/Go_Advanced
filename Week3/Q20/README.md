# 問20｜メッセージキュー（Pub/Sub）基礎

## 目標
マイクロサービス間での非同期通信パターン「Pub/Sub（パブリッシュ・サブスクライブ）」の概念を、Goのチャネルを使ったシミュレーションで理解します。

## 今回の演習で学ぶこと
この問題では、マイクロサービス間での非同期通信パターン「パブサブ（発行・購読）」モデルを、ゴーのチャネルを使ったシミュレーションを通じて、以下の3つの重要ポイントに注目して学びます。

**1. サブスクライバー（購読者）の待ち受け**
「誰かから郵便物が届かないかな」とポストの前でずっと待ち構えている受信側の仕組みです。
```go
go func() { // メインの処理を止めないよう、別の人（ゴルーチン）を待たせる
    for msg := range messageQueue {
        fmt.Printf("受信: %s\n", msg) // 届いたらすぐに処理をする
    }
}()
```
- `for msg := range ...`: チャネル（メールボックス）にデータがある限り何度も取り出し、空っぽになれば新しいデータが投入されるまで自動的におとなしく待機（ブロック）してくれます。

**2. パブリッシャー（発行者）の送信処理**
「これやっといて！」というメッセージを書いた手紙を、ポストにポイッと投げ込む送信側の仕組みです。
```go
messageQueue <- "新着ニュース"
```
- メールの送信処理や画像の圧縮など時間のかかる処理を、ユーザーを待たせたままその場で実行するのではなく、この「キュー」に放り込むのがポイントです。
- 投げ込んだ瞬間にメインの処理は「受け付け完了しました！」と（相手が処理を終えるのを待たずに）すぐに画面へ応答を返せるため、ユーザーも快適です（これが非同期のメリットです）。

**3. 終了通知（Close）**
「本日の営業は終了しました（もう手紙は来ません）」と宣言する後片付けの工程です。
```go
close(messageQueue)
```
- チャネルをクローズすることで、待ち構えていたサブスクライバーの `range` ループが「あ、もう待たなくていいんだな」と悟って綺麗に終了（ログアウト）してくれます。この終了通知がないと、永遠に待ち続けてメモリを食い潰すゴルーチンリークの原因になります。




**パブサブパターンの利点**
送信側（Publisher）と受信側（Subscriber）が直接お互いを知らなくていい「疎結合」な状態を作れます。これにより、重い処理をバックグラウンドに逃がしたり、システムの一部が止まってもメッセージをキューに溜めておけたりと、非常に柔軟で頑丈なシステムを構築できます。

1. `for msg := range messageQueue` でメッセージを受信して `"Sending email to: " + msg` を出力するゴルーチンを起動してください。
