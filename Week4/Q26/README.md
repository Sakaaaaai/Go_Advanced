# 問26｜Docker マルチステージビルド

## 目標
Goアプリを本番環境向けの軽量コンテナとしてパッケージングするための「マルチステージビルド（Multi-stage Build）」を用いたDockerfileの書き方を学びます。

## 今回の演習で学ぶこと
この問題では、Go言語の「単一バイナリ」という強みを最大限に活かして、本番環境向けの超軽量なコンテナを作るための「マルチステージビルド」の書き方を、以下の3つの重要ポイントに注目して学びます。

**1. ビルド用ステージの定義（AS builder）**
ソースコードをコンパイルするためだけの、様々な道具（Goコンパイラなど）が詰まった「作業部屋（巨大なコンテナ）」を作る工程です。
```dockerfile
FROM golang:1.20 AS builder  # この作業部屋に「builder」という名前をつける
WORKDIR /app                 # 作業机
COPY . .                     # ソースコードを持ち込む
RUN go build -o server main.go # コンパイルして実行ファイル(server)を作る
```
- この `builder` ステージのイメージサイズは約1GB近くあり、非常に巨大です。これをそのまま本番環境に持っていくのは、通信量や起動速度の面で大赤字になります。

**2. 実行用ステージの切り替え**
作業部屋はそのまま捨てて、新しく本番環境用の「超スリムな部屋（軽量コンテナ）」を用意する工程です。
```dockerfile
FROM alpine:latest
```
- `FROM` を2回書くのがマルチステージビルドの極意です。
- `alpine` はコンパイラも何もない、わずか数MBの極小Linuxです。Goは「ビルドさえしてしまえば、Linux上で単独で動く一つのバイナリファイルになる」という超強力な特性があるため、巨大なGoコンパイラ群は本番環境には全く不要なのです。

**3. バイナリの移動処理（--from=builder）**
1段階目の作業部屋（builder）で作った「完成品のファイル」だけを、2段階目のスリムな部屋へコピーしてくる工程です。
```dockerfile
COPY --from=builder /app/server /server
```
- この1行により、無駄なソースコードや重いツール類が一切含まれず、純粋に「動くプログラムファイル1つだけ」が入った数MBの神のように軽いDockerイメージが完成します。サイズが小さい分、セキュリティのリスク（攻撃される隙）も激減するため、現代のコンテナ開発においてこの手法は絶対の標準（デファクトスタンダード）です。




**小さくて安全なコンテナ**
マルチステージビルドを使うと、イメージサイズが劇的に小さくなるだけでなく、コンテナ内に余計なツール（シェルやコンパイラ）が含まれなくなるため、セキュリティ上のリスクも激減します。マイクロサービスのデプロイにおいて、この手法は必須のテクニックです。

## 問題文
定数 `DockerfileContent` を完成させてください：

1. `golang:1.20 AS builder` でビルドステージを開始してください。
2. `/app` を作業ディレクトリに設定し、`go build -o server main.go` でビルドしてください。
3. `alpine:latest` で本番ステージを開始してください。
4. `COPY --from=builder /app/server /server` でバイナリをコピーしてください。
5. `CMD ["/server"]` で起動コマンドを指定してください。

- `COPY --from=builder` で前ステージのファイルをコピーする
