# 問25｜結合テスト（Testcontainers活用）

## 目標
本物のDBをDockerコンテナとして立ち上げてテストを実行する「結合テスト（Integration Test）」の考え方と、テスト用フィクスチャパターンを学びます。

## 今回の演習で学ぶこと
この問題では、本物のデータベースをドッカーコンテナとしてその都度立ち上げてテストを実行する「結合テスト」の考え方と、テスト用フィクスチャパターンを、以下の3つの重要ポイントに注目して学びます。

**1. セットアップ処理の実装**
テストを実行する直前に、本物のデータベース（の入ったDockerコンテナ）を全自動で新品の状態でポコッと立ち上げる工程です。
```go
func setupDB() (string, func()) {
    // 実際にはここでTestcontainers等のライブラリを使い、Dockerコンテナを起動する
    url := "postgres://testuser:pass@localhost:5432/testdb"
    // ... コンテナ起動処理
```
- なぜわざわざ立ち上げるのか？ モック（影武者）を使ったユニットテストでは、「SQLの文法ミス」や「テーブルの制約違反」を見つけることができないからです。本番と全く同じ環境を使い捨てで用意することで、最も信頼性の高い「結合テスト」が可能になります。

**2. クリーンアップ関数の返却**
テストが終わった後に、立ち上げたコンテナを「確実に消し去るための掃除スイッチ（関数）」を作って返す、Go特有の大切な作法です。
```go
cleanup := func() {
    // コンテナの停止・削除処理
    fmt.Println("使い終わったDBコンテナを破棄します。")
}
return url, cleanup // 接続先URLと、掃除用スイッチをセットで返す
```
- このように、準備（Setup）と片付け（Teardown）をセットにして扱う設計手法を「テスト・フィクスチャ・パターン」と呼びます。

**3. 遅延実行による確実な破棄（Defer）**
受け取った「掃除スイッチ」を、絶対に押し忘れないようにする工夫です。
```go
url, cleanup := setupDB() // 準備完了
defer cleanup()           // 「終わったら必ずこのスイッチを押してね」と予約
```
- `defer` の魔法により、中でめちゃくちゃなエラーが起きてテストがパニックで異常終了したとしても、最後に必ず `cleanup()` が実行されます。これにより、パソコンの中に「消し忘れたゴミのコンテナ」が大量に溜まって重くなるのを防ぎます。




**モックでは見抜けないバグを叩く**
SQLの構文ミスや、テーブルの制約違反（ユニーク制約など）は、モックを使ったテストでは絶対に見つけることができません。重要な機能には、この結合テストを併用して、本番環境での「動かない」をゼロにしましょう。
