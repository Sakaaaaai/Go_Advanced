# 問23｜依存性の注入（Dependency Injection）とWire

## 目標
コンポーネント間の依存関係を手動でつなぎ合わせる「依存性の注入（DI: Dependency Injection）」の仕組みと、それを自動化する `google/wire` の考え方を学びます。

## 今回の演習で学ぶこと
この問題では、層に分かれた各パーツを正しい順序で組み立てる「依存性の注入（DI）」を、以下の3つの重要ポイントに注目して学びます。

**1. 最も外側のインフラから作る**
パズルの土台となる、データベース接続などの物理的な道具（インフラストラクチャ）を一番最初に準備する工程です。
```go
// MySQLなどに実際につながるオブジェクトを生成
db := NewDatabase()
```
- Q22のクリーンアーキテクチャでは、上位層（ユースケースなど）の中では下位層（データベースなど）を作らないという鉄則がありました。そのため、一番外側の `main` 関数などで下位層の実体を先に作っておく必要があります。

**2. 依存関係を順番に繋いでいく**
作っておいた道具（下位層の実体）を、それを必要としている人（上位層）へ「外から渡してあげる」工程です。
```go
// 「このdbを使ってね」と、リポジトリ層に注入する
repo := NewRepository(db)
```
- この「使う道具を、使う人の内部で作るのではなく、外から引数等でポイッと渡してやる（注入する）」という単純な行為こそが、「依存性の注入（DI: Dependency Injection）」の正体です。これにより、いつでも別の道具に入れ替える（例えばテスト時にはモックを渡す）ことが可能になります。

**3. 最終的なサービスの完成**
出来上がったパーツをマトリョーシカのようにさらに上位の層へ組み込み、全体を完成させます。
```go
// 出来上がったrepoを、さらに上位のservice層に注入する
service := NewService(repo)
```
- これで「DB」→「リポジトリ」→「サービス（ユースケース）」と鎖のように繋がり、アプリケーションが動き出す準備が整いました。
- 大規模なアプリではこの「手で順番に組み立てるコード（手動DI）」が数百行にもなるため、これを設計図だけ書いて自動生成してくれるのが、Googleの `wire` などの「DIコンテナ（DIライブラリ）」の役割です。




**手動DIから自動DIへ**
大規模な開発では、この「手で組み立てるコード（コンストラクタの呼び出し）」が何百行にもなってしまい大変です。その面倒な手順を、依存関係の宣言さえしておけば自動でプログラムとして書き出してくれるのが、`wire` などのDIライブラリの役割です。

## 問題文
`main.go` の `___` の部分を埋めてプログラムを完成させてください。

`InitializeService()` 関数を完成させてください：
1. `NewDatabase()` でDBを作成してください。
2. `NewRepository(db)` でリポジトリを作成してください。
3. `NewService(repo)` でサービスを作成して返してください。

```bash
cd /workspaces/Go_Advanced/Week4/Q23

```
