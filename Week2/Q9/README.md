# 問9｜コネクションプールのチューニング

## 目標
Goの `database/sql.DB` が内部に持つ「コネクションプール」の設定を理解し、適切にチューニングする方法を学びます。

## 今回の演習で学ぶこと
この問題では、データベースへの無駄な接続生成を抑え、パフォーマンスを最大化する「コネクションプール」の設定方法を、以下の3つの重要ポイントに注目して学びます。

**1. 最大接続数（SetMaxOpenConns）の設定**
同時にデータベースへつなぐことができる接続（コネクション）の「最大の上限枠」を決める設定です。
```go
db.SetMaxOpenConns(25)
```
- もしこの上限を設定しないと、アクセス集中時にGoアプリが無限にDBへ接続しに行き、DBサーバー側が悲鳴を上げてダウンしてしまいます（Too many connectionsエラー）。
- 上限（ここでは25）を決めておくことで、それ以上のリクエストが来ても、Go側が「誰かの接続が終わるまで順番待ち」の形をとってくれ、システム全体をパンクから守ります。

**2. アイドル接続数（SetMaxIdleConns）の設定**
誰も使っていない（暇な）状態でも、切断せずに「キープ」しておく接続の数の設定です。
```go
db.SetMaxIdleConns(25)
```
- DBへの接続作業（TCPハンドシェイクや認証など）は非常に重たい処理です。リクエストが来るたびに道を作り直すのは大きな時間のロスになります。
- アイドル接続をプール（貯水池のように保持）しておくことで、リクエストが来た瞬間に素早く処理を開始でき、レスポンス速度が劇的に向上します。通常、`MaxOpenConns` と同等の値に設定するのがベストプラクティスです。

**3. 最大生存期間（SetConnMaxLifetime）の設定**
1度作った接続を、最大で「どのくらいの期間」使い回すかという寿命の設定です。
```go
db.SetConnMaxLifetime(5 * time.Minute) // 5分で寿命を迎える
```
- いくらキープしておくと言っても、永遠に繋ぎっぱなしにしていると、DB側のネットワーク機器（ファイアウォールなど）が「誰も通信していないから勝手に切断しよう」と一方的に線を切ってしまうことがあります。
- ここで寿命（例えば5分）を設定しておけば、Go側で定期的に古い接続を捨てて新しい接続を作り直す（リフレッシュする）ため、突然の通信エラーを防ぐ頑丈なシステムになります。




**適切に設定しないとどうなる？**
設定が小さすぎると「接続待ち」でアプリが激重になり、逆に大きすぎるとDBサーバー側の接続上限に達してしまい、エラーを吐いて止まってしまいます。サーバーのスペックに合わせて最適なバランスを見つけることが重要です。
